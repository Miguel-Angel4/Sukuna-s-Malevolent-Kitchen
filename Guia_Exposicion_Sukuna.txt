========================================================================
GUÍA TÉCNICA DE EXPOSICIÓN: SUKUNA'S MALEVOLENT KITCHEN
========================================================================

Esta guía detalla el funcionamiento interno de la aplicación. Está pensada 
para demostrar dominio técnico sobre el código (JavaScript, CSS, DOM y Base de Datos)
explicándolo de manera clara y profesional ante un tribunal.

------------------------------------------------------------------------
1. EL SISTEMA DE AUDIO PERSISTENTE E INTELIGENTE (music.js)
------------------------------------------------------------------------
El principal desafío en aplicaciones con múltiples páginas (Multi-Page Apps)
es mantener la música sonando sin interrupciones al cambiar de HTML.
Lo hemos resuelto de la siguiente manera:

- Persistencia con `localStorage`: Usamos el evento de ventana `beforeunload` 
  (justo antes de que el usuario cambie de pestaña) para capturar el 
  `audio.currentTime` (el segundo exacto por el que va la canción) y 
  guardarlo en el caché del navegador (`localStorage`). Al cargar la nueva 
  página (`DOMContentLoaded`), el script lee ese caché y aplica el tiempo 
  al objeto `Audio`, dándole a Play. Para el usuario, el corte es casi imperceptible.
  
- Transiciones de Audio Dinámicas: Cuando se abre un minijuego, llamamos 
  al método `playGame(personaje)`. Este ejecuta un "Fade Out" programado 
  con `setInterval` que va restando volumen progresivamente (ej. -0.1 cada 50ms) 
  hasta silenciar el tema central, luego cambia la propiedad `.src` del audio 
  a la pista de combate del minijuego. Cuando el juego termina, se hace la 
  inversa ("Fade In") y se restaura el tema original.

------------------------------------------------------------------------
2. ARQUITECTURA DE LOS MINIJUEGOS (games.js)
------------------------------------------------------------------------
Los minijuegos no cargan pantallas nuevas; funcionan inyectando código HTML 
dinámicamente en el DOM (dentro del contenedor `#game-modal`) mediante 
la propiedad `innerHTML`. Todo corre sobre "Event Loops" (Bucles de eventos) 
basados en `setInterval` y `setTimeout`.

* AHORCADO (Gojo Satoru):
  - Lógica: Usamos un Array con la palabra oculta y otro Array relleno 
    de guiones bajos ("_"). Al pulsar un botón generado dinámicamente 
    con JS, comprobamos con `includes()` si la letra está. Si está, 
    reemplazamos el índice correspondiente; si no, restamos de la variable `intentos`.
  - Cronómetro: Un `setInterval` ejecuta una resta constante a una 
    variable `timer`.

* KOKUSEN / BLACK FLASH (Yuji Itadori):
  - Lógica: Un script genera elementos `<div>` que actúan como "objetivos". 
    Usamos `Math.random()` para asignarles posiciones absolutas (Ejes X e Y) 
    dentro del contenedor. 
  - Limpieza del DOM: Cada objetivo tiene asignado un `setTimeout` interno 
    que hace un `.remove()` de sí mismo a los pocos segundos. Si el usuario 
    hace click a tiempo (evento `onclick`), se elimina y suma puntuación.

* EL CORTE (Ryomen Sukuna):
  - Lógica de movimiento: Un `setInterval` actualiza una variable `pos` 
    sumando y restando. Esta variable se inyecta directamente en el CSS 
    (`left: ${pos}%`) de una barra deslizante (slider) creando ilusión 
    de movimiento.
  - Colisión Matemática: Al pulsar espacio, el JS frena el bucle y 
    comprueba matemáticamente si el valor `pos` (por dónde iba el slider) 
    se encuentra dentro del rango numérico aleatorio del `hitZonePos` 
    (la zona roja).

* JACKPOT (Kinji Hakari):
  - Lógica: Un Array con emojis. Al tirar de la palanca se activa un 
    bucle súper rápido que inyecta en el DOM 3 elementos aleatorios del 
    Array usando `Math.floor(Math.random() * array.length)`. A los 20 ciclos,
    se detiene (`clearInterval`) y si los tres índices coinciden, es victoria.

3. CONEXIÓN BACKEND Y SISTEMA DE RECOMPENSAS (Supabase)
------------------------------------------------------------------------
No hay base de datos local; el sistema escala mediante la nube usando Supabase 
(PostgreSQL).

- Sesiones (Auth): Usamos JSON Web Tokens (JWT) gestionados por la librería 
  de Supabase. En las páginas críticas (como "Mis Recompensas"), la función 
  `sb.auth.getUser()` verifica si el Token del usuario activo es válido antes 
  de pintar ningún dato sensible.
  
- Inserción de Recompensas: Cuando la función `saveReward()` es llamada al 
  ganar un minijuego, ejecuta una consulta asíncrona (`await supabase.from...`) 
  que inserta una fila conteniendo: ID del usuario, juego jugado, porcentaje de 
  descuento, el código (ej. GOJO25) y calcula con SQL puro una fecha de expiración 
  sumando 30 días (`interval '30 days'`).

- Generación de Código QR en vivo: En lugar de guardar imágenes pesadas en la base 
  de datos, guardamos solo el string del código. En el front-end (recompensas.html), 
  JS coge ese string y lo interpola en una URL de la API pública "qrserver.com", 
  esculpiendo un `<img>` que renderiza mágicamente el QR al vuelo.

------------------------------------------------------------------------
4. RENDIMIENTO VISUAL Y ADAPTABILIDAD (CSS)
------------------------------------------------------------------------
Todo el código CSS fue purgado de márgenes fijos (`margin-left: 1000px`) y 
está construido sobre contenedores `Flexbox` y `Grid` que fluyen como el agua.
Usamos *Media Queries* agresivas: cuando la resolución de pantalla cae por debajo 
de 768px (Móviles), el layout en inyecta reglas con `transform: scale()` para 
los minijuegos, asegurando que las "hit-boxes" (cajas de impacto de Yuji o Sukuna) 
y sprites disminuyan un 60%, encajando a la perfección sin romper la web (y 
haciéndolo intencionadamente más difícil para el usuario móvil).
